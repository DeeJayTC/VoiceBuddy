# Multilingual Support - Quick Reference

## What's New

VoiceBuddy now supports multiple languages! The system includes:
- English (en) - always available
- Spanish (es) - example translation included
- Any other language supported by DeepL API (de, fr, it, nl, pl, pt, ja, zh, ko, etc.)

## User Guide

### Changing the Application Language

1. Open VoiceBuddy
2. Go to the **Settings** tab
3. Find the **Application language** section at the bottom
4. Select your preferred language from the dropdown
5. **Restart the application** for changes to take effect

### Available Languages

- **en** - English (default)
- **es** - Spanish (example)
- More languages available after running the build script

## Developer Guide

### Adding New UI Text

1. **Edit** `src/VoiceBuddy.App/Strings/Strings.en.json`
   ```json
   "Settings": {
     "NewLabel": "This is new text"
   }
   ```

2. **Use in C# code**:
   ```csharp
   using VoiceBuddy.Services;
   
   var text = LanguageManager.Instance.GetString("Settings.NewLabel");
   ```

3. **Use in event handlers** (code-behind):
   ```csharp
   private void UpdateLabel()
   {
       MyLabel.Content = LanguageManager.Instance.GetString("Settings.NewLabel");
   }
   ```

### Generating Translations with DeepL

The `build/translate-strings.ps1` script automates everything:

```powershell
# Set your DeepL API key
$env:DEEPL_API_KEY = "YOUR_KEY_HERE"

# Run the translation script
cd build
.\translate-strings.ps1

# Or specify languages
.\translate-strings.ps1 -Languages "de,fr,es,it,ja,zh"
```

**Smart Features:**
- ✅ **Change detection**: Only translates if English file changed (saves API quota)
- ✅ **Batching**: Sends 50 strings per API request (efficient)
- ✅ **Fallback**: Missing translations fall back to English
- ✅ **Hash tracking**: `.strings-hash` file tracks changes

### File Structure


## API Documentation

### LanguageManager Class

```csharp
// Get the singleton instance
var mgr = LanguageManager.Instance;

// Get available languages
List<string> langs = mgr.GetAvailableLanguages();
// Returns: ["en", "es", "de", "fr", ...]

// Set the current language
mgr.SetLanguage("es");  // Switch to Spanish

// Get a translated string
string text = mgr.GetString("Overview.Device");
// Returns: "Dispositivo" (in Spanish) or "Device" (fallback to English)

// Get the current language
string current = mgr.CurrentLanguage;  // Returns: "es"
```

### Settings Model

```csharp
// Get current setting
string lang = App.Settings.Current.UILanguage;  // "es", "de", etc.

// Change language (saves to settings.json)
App.Settings.Current.UILanguage = "de";
App.Settings.Commit();  // Persist to disk
```

## Common Tasks

### Task: Add a new label to the UI

1. Add to `Strings.en.json`:
   ```json
   "MySection": {
     "MyNewLabel": "My label text"
   }
   ```

2. Use in MainWindow.xaml.cs:
   ```csharp
   myLabel.Content = LanguageManager.Instance.GetString("MySection.MyNewLabel");
   ```

3. Rebuild and test with English
4. Run translation script to generate other languages

### Task: Switch to German in tests

```csharp
LanguageManager.Instance.SetLanguage("de");
// Verify UI loads German text
```

### Task: Update a Spanish translation

1. Edit `src/VoiceBuddy.App/Strings/Strings.es.json` directly
2. Rebuild
3. Restart app and select Spanish to test

### Task: Add Chinese support

```powershell
$env:DEEPL_API_KEY = "your-key"
cd build
.\translate-strings.ps1 -Languages "zh"
```

Then rebuild and Chinese (zh) will appear in the language picker.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| Language picker shows no languages | Run `dotnet build` to copy Strings files to output |
| Text still in English after switching | Remember to restart the application |
| Build script fails with API error | Check `DEEPL_API_KEY` is set and API quota available |
| Missing translation in a language | Check Strings.{lang}.json is in output directory; fallback to English is automatic |
| Language file seems incomplete | Run build script to regenerate; incomplete files get filled with English fallback |

## Performance Notes

- String files (~5KB each) loaded once at startup into memory
- Change detection saves 95%+ of translation API calls
- No performance impact to app runtime

## Limits & Notes

- **Restart required**: Full UI refresh needs app restart (XAML binding limitation)
- **Fallback**: Missing keys automatically fall back to English
- **Case-sensitive keys**: "Overview.Device" ≠ "overview.device"
- **Valid JSON required**: Malformed JSON files silently fall back to English

## 🚀 How to Use

### For End Users
1. Go to **Settings** tab
2. Find **Application language** section
3. Select desired language from dropdown
4. Restart the app
5. UI now displays in selected language

### For Developers

#### **Add a new string to the UI:**
```csharp
// 1. Add to Strings.en.json
{
  "MySection": {
    "MyKey": "My text here"
  }
}

// 2. Use in code
var text = LanguageManager.Instance.GetString("MySection.MyKey");
```

#### **Generate translations via DeepL:**
```powershell
$env:DEEPL_API_KEY = "your-api-key"
cd build
.\translate-strings.ps1 -Languages "de,fr,es,it,ja,zh,ko"
```

#### **Switch language at runtime:**
```csharp
LanguageManager.Instance.SetLanguage("de");  // Switch to German
// Note: Full UI update requires app restart (current limitation)
```

## 📊 Supported Languages

Build script supports all DeepL API languages:
- German (de), French (fr), Spanish (es), Italian (it)
- Dutch (nl), Polish (pl), Portuguese (pt), Russian (ru)
- Japanese (ja), Chinese (zh), Korean (ko), and more

Default: English (en) — always available as fallback

## 🏗️ Technical Details

### File Organization
```
src/VoiceBuddy.App/
├── Strings/
│   ├── Strings.en.json        (English source, ~100 strings)
│   ├── Strings.es.json        (Spanish example)
│   ├── Strings.de.json        (auto-generated by build script)
│   ├── Strings.fr.json        (auto-generated by build script)
│   └── .strings-hash          (change detection hash)
├── Services/
│   └── LanguageManager.cs     (runtime string loading)
├── Views/
│   └── MainWindow.xaml.cs     (language picker event handlers)
└── VoiceBuddy.App.csproj      (deployment configuration)

build/
└── translate-strings.ps1      (automated translation script)
```

### Change Detection Algorithm
```
On run:
  1. Read Strings.en.json
  2. Compute SHA256 hash
  3. Compare with .strings-hash
  4. If different:
     - Flatten JSON keys
     - Batch send to DeepL API (50 strings/request)
     - Unflatten results into language-specific JSON
     - Save each Strings.{lang}.json
     - Update .strings-hash
  5. If same:
     - Skip translation (API quota saved!)
```

### Runtime Loading
```
App startup:
  1. LanguageManager.Instance.SetLanguage("en")  (or saved preference)
  2. Loads Strings.{lang}.json into memory
  3. On language picker change: Reload and save to settings
  4. GetString("key.path") returns translated text
```

## ⚠️ Current Limitations & Future Work

- **XAML binding**: Currently, text changes require app restart due to XAML template binding limitations
  - Future: Implement `IValueConverter` + `DynamicResource` for hot language switching
- **Partial translations**: If a language file is incomplete, missing keys fall back to English
- **No RTL support**: Right-to-left languages (Arabic, Hebrew) not yet supported
- **No locale formatting**: Date/time/number formatting is not localized
